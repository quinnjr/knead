# @hpmws/graphql

Code-first GraphQL for hpmws on the [Leaven](https://github.com/quinnjr/leaven) engine. Types are TC39-decorated classes, and a GraphQL field type that disagrees with its TypeScript field type is a compile error. Resolvers are ordinary providers that use `inject()`. The endpoint is an ordinary `@hpmws/http` route, so CORS, rate limiting, security headers and global guards apply to it unchanged.

```ts
@ObjectType()
class User {
  @Field(() => ID) id!: string;
  @Field(() => String, { nullable: true }) bio?: string | null; // nullable needs null | undefined
  @Field(() => [Post]) posts!: Post[];
}

@Resolver(() => User)
class UserResolver {
  readonly #users = inject(UsersService);

  @Query(() => User, { args: { id: ID } })
  user(ctx: ResolverCtx<{ id: string }>) {
    return this.#users.get(ctx.args.id);
  }

  @ResolveField(() => [Post])
  posts(ctx: ResolverCtx<{}, User>) {
    return ctx.loader(PostsByAuthor).load(ctx.parent.id); // one batch per operation tick
  }
}

@Module({
  imports: [GraphQLModule.forRoot({ context: (http) => ({ user: http.state.user }) })],
  providers: [UsersService, PostsByAuthor, UserResolver],
})
class AppModule {}
```

- **Scalars:** `ID`, `Int` and `Float` are exported handles. For strings and booleans, use the global `String` and `Boolean`; `Number` maps to `Float`. Use `defineScalar<T>()`, `defineEnum()` and `defineUnion()` for other types. Lists are written `() => [T]` with `nullable: 'items' | 'list' | 'both'`.
- **Arguments:** an inline or `@Field` `defaultValue` must be a value of the declared type (compile error otherwise). Pass an inline map (`{ first: Int, after: { type: () => ID, nullable: true } }`) or an `@ArgsType()` class (`args: PageArgs`), but not both at once. `validate: { arg: standardSchema }` runs after GraphQL coercion, and a failure is reported as `BAD_USER_INPUT` with `extensions.issues`.
- **Guards and metadata:** `guards` options and `@UseGuards()` on the class or method receive the `ResolverCtx`, and class guards run first. A guard passes only when it returns (or resolves to) exactly `true`, as in the `@hpmws/http` pipeline; any other value, including a truthy object, string or number, produces `FORBIDDEN`. Values from `createRouteDecorator()` appear in `ctx.meta`. Global `APP_GUARD` guards run once per HTTP request and once per WebSocket upgrade (with `ctx.route` set to `null` and `ctx.upgrade` set), not per resolver.
- **Module guards and default deny:** `GraphQLModule.forRoot({ guards })` runs guards on every root field (queries, mutations and subscriptions, at subscribe time) before the resolver's class and method guards; `@ResolveField` methods are not affected. `@Public()` on a resolver class or root field skips the module guards (its own guards still run) and sets `ctx.meta[IS_PUBLIC]`. It is GraphQL-only: HTTP global guards (`APP_GUARD`, `useGlobalGuards()`) still run on the `/graphql` request itself, and a global guard that should let public operations through has to allow the GraphQL route on its own terms. With `defaultDeny: true`, a root field that is neither `@Public()` nor protected by a guard of its own (class `@UseGuards`, the `guards` option or method `@UseGuards`) is `FORBIDDEN`; module guards do not count, so every field states its authorization explicitly. `defaultDeny` protects entry points only (root query, mutation and subscription fields): `@ResolveField` methods and plain `@Field` properties are reachable from any root field that returns their type, so sensitive data there needs its own guards (move a sensitive `@Field` into a guarded `@ResolveField`). Guards run before the `validate` schemas, so they see the coerced but unvalidated arguments; put authorization that depends on validated or transformed arguments in the resolver's `authorize` guards, which run after `validate` and see the schema output in `ctx.args` (anything but `true` is `FORBIDDEN`). Guard references are checked at bootstrap like HTTP guards: `undefined` (a circular import), an arrow-function `canActivate` field or an object without `canActivate()` is an `HttpConfigError` naming the resolver (or `GraphQLModule guards`), and never counts as a guard for `defaultDeny`.
- **Typed resolvers:** in `@Resolver(() => User)`, a `ResolverCtx<Args, Parent>` parent must accept a `User`. Subscription methods take `SubscriptionCtx<Args, Payload>`, whose parent is the event. The check runs on the class, which can't tell decorated methods from undecorated ones, so it applies to every public method whose first parameter is a `ResolverCtx`. A helper that takes a context for a different parent must be `#private`.
- **Errors:** `BadRequestException` maps to `BAD_USER_INPUT`, `UnauthorizedException` to `UNAUTHENTICATED`, `ForbiddenException` to `FORBIDDEN`, `NotFoundException` to `NOT_FOUND` and `TooManyRequestsException` to `RATE_LIMITED`. A `LeavenError` keeps its own code, and a `GraphQLError` thrown by a resolver is sent as is. Variable and argument coercion errors are `BAD_USER_INPUT`; graphql-js quotes the offending value in their messages (`Variable "$p" got invalid value "…"`), so a client sees its own input echoed back, and so does any log or proxy that records responses. Any other error becomes `INTERNAL_SERVER_ERROR`, including graphql-js output errors (such as a resolver returning an object for a `String` field) and errors thrown by `hooks`, subscription `filter`s or the `context` factory over WebSocket. It is logged under a correlation id, which the client gets as `extensions.correlationId`, and its message is masked unless `maskErrors: false`. Logging goes through `@hpmws/http`'s `logError()`: in development (`HTTP_DEVELOPMENT`, else `NODE_ENV=development`) the log entry carries the full error, redacted with `redactValue()`; otherwise it holds only the error's name and its message, redacted first and then truncated to 500 characters, never the object (its stack, cause or properties). The redaction happens before `LOGGER` is called, so it holds for any logger (pino, winston, ...). Leaven's own diagnostics (`leavenLogger`), subscription and `RedisPubSub` errors are logged the same way.
- **Limits:** every operation, over HTTP and WebSocket, is checked against `maxQueryLength` (default 100 KiB, checked before parsing, `400` over HTTP), `parseOptions.maxTokens` (default 3000), `maxFields` (default 1000 field selections, `FIELD_LIMIT`, counted both as written in all operations and fragments, including fragments that are never spread, and with fragments expanded where they are spread; checked right after parsing, before validation, whose overlapping-fields rule is quadratic in repeated fields, and before the document is cached), `maxDepth` (default 10, with fragments expanded, `DEPTH_LIMIT`; hpmws checks it itself and does not count selections inside `__schema` and `__type`, so `getIntrospectionQuery()` works for the playground and codegen; those selections have their own cap, `maxIntrospectionDepth`, default 15, the depth of `getIntrospectionQuery()`, counting the `__schema`/`__type` field as level 1, so an introspection bomb is still `DEPTH_LIMIT`), `maxAliases` (default 30 per document, `BAD_USER_INPUT`) and `maxComplexity` (default 1000, `COMPLEXITY_LIMIT`; a field's cost is its `complexity` option, default 1). Leaven's document cache defaults to `cache: { maxSize: 100 }` (each entry keeps a whole AST); pass your own `cache`, or `false`, to change it. `getIntrospectionQuery()` (220 fields, 163 tokens, introspection depth 15) passes every default. Leaven's complexity calculator counts introspection fields like any other (cost 1 plus half the depth), so `maxComplexity` also bounds introspection; `getIntrospectionQuery()` with every option enabled costs about 1009 and needs a slightly higher `maxComplexity`. Validation still costs CPU per request, so also rate-limit the GraphQL route (for example with `@hpmws/rate-limit`). Raise a limit by setting a larger number, or disable it with `Infinity` or `false`; other values are a configuration error. The defaults are exported as `GRAPHQL_LIMITS`. Relay-style schemas spend three levels per connection (`users { edges { node { ... } } }`), so a query two connections deep already reaches depth 7: raise `maxDepth` (for example to 15) to fit your deepest legitimate query, and keep `maxComplexity` as the guard against wide queries.
- **HTTP:** `POST` requires `Content-Type: application/json` (otherwise `415`) and runs queries and mutations; a subscription is `400`. `GET` runs queries only (otherwise `405`) and requires one of the `csrf.requiredHeaders` (default `x-graphql-request`). The operation type is checked on the document Leaven parses and executes, so the check honours `parseOptions` and the document cache. Requests that name `application/graphql-response+json` in `Accept` (with a q value at least that of `application/json`) get GraphQL-over-HTTP status codes: `400` for a rejected request (including a missing or unknown operation name), `500` only for `INTERNAL_SERVER_ERROR`. All other requests get `200`. GraphQL responses carry `cache-control: no-store` (they often hold per-user data; set `cacheControl` to another value, or `false` to send none) and `x-content-type-options: nosniff`. A `GET` request carries its query and `variables` in the URL, which proxies, access logs and browser history record: send tokens, passwords and other sensitive values in a `POST` body instead.
- **Subscriptions:** a `graphql-transport-ws` connection on the same path that runs subscription operations only; a query or mutation sent over it gets a `BAD_USER_INPUT` error and never executes. `@Subscription(() => T, { topic, filter?, resolve? })` uses the `PUBSUB` engine. A `topic` function usually embeds client input, so a topic it returns that contains `*` or `#` (wildcards on engines with pattern subscriptions) is rejected with `BAD_USER_INPUT` before anything subscribes, and so is one longer than 256 characters; static topic strings may use wildcards. The engine defaults to an in-memory `PubSub`. Use `new RedisPubSub({ url })` (on `Bun.redis`, with a dedicated subscriber connection) when several instances run; a failed Redis connection is logged, ends the affected subscriptions, and is retried by the next subscriber. `publish()` never rejects: a failed publish is logged and the event is lost, so fire-and-forget calls are safe; use `publishOrThrow()` when the caller must know. A publish waits at most `publishTimeout` (default 2000 ms) for Redis: past it, `publish()` logs and resolves and `publishOrThrow()` rejects. Give a caller-supplied `client` `enableOfflineQueue: false` and a `connectionTimeout`, so commands fail fast while Redis is unreachable instead of queueing. In production, connect with `rediss://` (TLS) as an ACL user allowed only the `PUBLISH`/`SUBSCRIBE` commands on the prefix's channels (for example `ACL SETUSER gql on >secret resetchannels &hpmws:gql:* -@all +publish +subscribe +unsubscribe +ping`); a plaintext `redis://` or `valkey://` URL (from `url`, `REDIS_URL` or `VALKEY_URL`) to a non-loopback host logs a warning at construction, and `requireTls: true` makes it throw instead (a caller-supplied `client` bypasses the check: configure TLS on it yourself). Without `signingKey`, any client that can publish to the Redis server can inject subscription events, so a `RedisPubSub` without one whose server is not on loopback logs a warning at construction. Set `signingKey` (at least 32 bytes, the same on every instance) to sign each message with HMAC-SHA256 over the channel (prefix and topic), a timestamp and the payload: messages without a valid signature (such as ones published by another Redis client, or replayed under another prefix or topic), older than `maxSignatureAge` (default 60s, at most 10 minutes) or dated more than 60s ahead are dropped and logged. Pass an array to rotate keys: messages are signed with the first key and accepted under any of them, so deploy `[new, old]` everywhere, then drop `old`. Generate a key with `openssl rand -base64 32` and load it from a secret store or the environment (`signingKey: process.env.REDIS_PUBSUB_SIGNING_KEY`); `Uint8Array` keys are copied at construction. Set `encryptionKey` (at least 32 bytes, the same on every instance; an array rotates like `signingKey`) to encrypt payloads with AES-256-GCM, a random 12-byte IV per message and the channel (prefix and topic) as additional authenticated data, so the Redis server and anything subscribed to it see only ciphertext and a message cannot be replayed on another topic; messages that fail to decrypt are dropped. Dropped messages (bad signature, stale, failed decryption, not JSON, or larger than `maxMessageBytes`, default 1 MiB, which is checked before any HMAC, decryption or JSON work) are reported at most once per 10 seconds per instance, with the number dropped since the previous report; `publishOrThrow()` rejects messages over `maxMessageBytes`. With both keys, the payload is encrypted and the envelope then signed. A captured message can still be replayed on the same channel within that window, so keep it short and don't rely on signing for exactly-once delivery. Each event gets fresh `ctx.loader()` DataLoaders and a fresh, empty `ctx.state`, so `ctx.state` written at subscribe time (by guards or the `topic` function, for example) is not visible to the resolvers of an event. Each operation on a socket also gets its own view of the upgrade request's `ctx.http` with its own `ctx.http.state`, a shallow copy of the upgrade's (headers, IP and the rest of the request are shared): an operation sees what middleware and guards set on the upgrade request (so `context: (http) => ({ user: http.state.user })` works), and state one operation writes is never visible to another. `ctx.meta` and the connection context (the `context` factory result and the object `onConnect` returned) are visible to every event. A subscriber that falls more than 1000 events behind drops the oldest, and a warning is logged. Event payloads are immutable: one payload is shared by every subscriber, so it is deep-frozen (`deepFreeze`, exported) when it arrives, both from the in-memory `PubSub` (which freezes the object you published, so publish a fresh DTO) and from `RedisPubSub`; build new objects in `resolve` instead of modifying the payload.
- **WebSocket authentication:** the upgrade request passes global middleware (CORS, rate limiting) and global `APP_GUARD` guards; a guard returning `false` is `403`. Browsers cannot set headers such as `Authorization` on a WebSocket, so an `APP_GUARD` that authenticates by header should let upgrades through (`ctx.upgrade` is `{ path }` on upgrades, `null` otherwise) and leave authentication to `subscriptions.onConnect`, which receives the client's `connectionParams`:

  ```ts
  const BearerGuard = (ctx: Ctx) => ctx.upgrade !== null || verify(ctx.req.headers.get('authorization'));
  GraphQLModule.forRoot({
    subscriptions: { onConnect: (_http, params) => verify(params.authorization) && { user: lookup(params) } },
  });
  ```

  Browser upgrades must come from the server's own origin, meaning the `Origin` host and port equal the request's `Host` header (default ports 80 and 443 are normalized, so `Host: app.example:443` matches `https://app.example`) and its scheme matches the connection (`https:` when `ctx.secure`, which honours a trusted proxy's `x-forwarded-proto`, otherwise `http:`), or from one of `subscriptions.allowedOrigins` (`'*'` allows any). `Origin: null` is rejected. The check is `@hpmws/http`'s `originAllowed`, run by `WsRegistry` before global guards. Upgrades without an `Origin` header (non-browser clients) are allowed. `@hpmws/http` has no forwarded-host setting, so behind a proxy that rewrites `Host` the same-origin check fails: list your public origins in `allowedOrigins` there. The scheme half needs care too. With hop-mode `trustProxy` (`trustProxy: 1`), `ctx.secure` comes from the `X-Forwarded-Proto` entry that many hops back, and a header with fewer entries than `hops` is ignored (then `ctx.secure` is the app's own TLS state, usually `false`). A proxy that overwrites the header instead of appending to it, such as nginx with `proxy_set_header X-Forwarded-Proto $scheme;` sitting behind a TLS-terminating load balancer, reports `http` for traffic that arrived over HTTPS. `ctx.secure` is then `false`, and the check rejects every `https://` page with `403`. Fix it in one of three ways:
  - make the proxy that faces the app pass the original value through (`proxy_set_header X-Forwarded-Proto $http_x_forwarded_proto;` when nginx is behind the load balancer, or `$scheme` only when nginx terminates TLS itself);
  - set `trustProxy` to the number of hops that each set the header;
  - list your public origins in `subscriptions.allowedOrigins`, which the scheme check does not affect. `onConnect(http, params)` runs on `connection_init` and can reject the connection (close code `4403`) or add values to its context. `params` (`ConnectionParams`, read-only) is whatever the client sent. **Never return `params` or spread it into the result**: the client would then choose its own context, such as `user` or `roles`. Return only values you derived and verified (`{ user: await verify(params.token) }`). The return type is `boolean | Partial<GraphQLContext>`, and returning or spreading `params` is a compile error. Resolver guards run once, when an operation subscribes, not per event, so by default authorization is decided when the socket connects and when each subscription starts. To revoke access later:
  - `@Subscription(() => T, { topic, recheckGuards: true })` re-runs the root guards (module, class and method) and then the `authorize` guards (against the validated arguments) before every event; an event they deny is delivered as `FORBIDDEN` (or the guard's own error) and the subscription completes. Rechecked guards see the identity from connect time (the `context(http)` and `onConnect` results), so on their own they only notice changes the guard looks up itself. Set `subscriptions.refreshContext({ http, context })` to do a live lookup before every recheck: its object result is merged over the operation's context (the guards and the event's resolvers see it) and `false` ends the subscription with `FORBIDDEN`. Real revocation therefore means one of: a live lookup (`refreshContext`, or inside the guard), `GraphQLSubscriptions.closeWhere`, or `maxConnectionLifetime`.
  - `subscriptions.maxConnectionLifetime` (ms) closes every socket with `4408` after that long, so clients reconnect and pass `onConnect` again.
  - `inject(GraphQLSubscriptions).closeWhere((connection) => connection.context.user?.id === id)` closes matching sockets (default code `1008`, reason `Connection revoked`) and returns how many it closed. A socket whose `onConnect` is still pending (or that has not sent `connection_init` yet) has no context to match, so the predicate is applied to it again once `onConnect` completes and the socket is closed then instead of being acknowledged. A predicate that throws for one socket is logged, and the others are still checked. `connection.http` is the upgrade `Ctx` and `connection.context` the connection's merged identity: the `context(http)` factory result, computed once when the connection initializes, with the object `onConnect` returned merged over it, so predicates can match on either. When nothing matches, a debug-level entry is logged.
- **WebSocket limits:** the subscription endpoint gets `@hpmws/http`'s WebSocket limits: `listen({ websocket })` sets the largest message (`maxPayloadLength`, default 256 KiB, above the 100 KiB `maxQueryLength` plus the message envelope, so an over-long query gets an `error` message and only a larger `subscribe` message drops the connection), backpressure, the idle timeout and the open sockets per client IP (default 100, `429` above it). `subscriptions.messageRate` overrides the per-socket message rate (default 100 messages per 10s; exceeding it closes the socket with `1008`). A `subscribe` whose query is longer than `maxQueryLength` gets an `error` message and never reaches Leaven. A second `connection_init` closes the socket with `4429` before `onConnect` runs again, and a `subscribe` or `complete` whose id does not match `^[A-Za-z0-9_.:-]{1,64}$` closes it with `4400` before the message reaches Leaven. When a socket closes, or a client sends `complete` for an id, every iterator for it is returned, including one whose `subscribe` was still resolving; a reused id returns the earlier iterator.
- **Shutdown:** the application calls `close()` on the pubsub engine, including one you passed in as `pubsub`.
- **Production defaults:** introspection and the playground are off, errors are masked and no schema file is written unless the application is in development: `HpmwsFactory.create(root, { development })` (the `HTTP_DEVELOPMENT` token), which itself defaults to `NODE_ENV=development`. An application created with `development: false` keeps these production defaults even when `NODE_ENV=development`. The playground is served only to requests that list `text/html` in `Accept`. Its page sends its own CSP, which allows its inline script by hash and only the exact `cdn.jsdelivr.net` asset URLs it loads (no third-party font hosts: Google Fonts is blocked and the page falls back to system fonts), and `referrer-policy: no-referrer`. The playground stores its tabs, queries and the headers you enter (including `Authorization` tokens) in the browser's `localStorage` for the page's origin: clear it after using a real token, and do not enable the playground on an origin that serves untrusted scripts. Those assets carry pinned Subresource Integrity hashes (`PLAYGROUND_ASSETS`); Leaven's inline script is pinned too (`PLAYGROUND_SCRIPT_HASHES`, the sha256 of the page rendered for `/graphql`; `playgroundScriptHashes()` recomputes it). If Leaven's page references an asset without a pinned hash, or its inline script differs, this is logged once at bootstrap and the playground answers `503`. The page's subscription URL is `playground.subscriptionEndpoint` when set (`playground: { subscriptionEndpoint: 'wss://api.example.com/graphql' }`, a `ws://`/`wss://` URL or an absolute path); otherwise it is derived from the request's `Host` header only when that is a plain `host[:port]`, and is the relative GraphQL path for anything else, so a forged `Host` never reaches the page. Enabling the playground while the application is not in development (`HTTP_DEVELOPMENT`, else `NODE_ENV`) logs a warning at bootstrap.
- **Bootstrap:** the schema is built and validated when the application is created. Errors name the class and field, for example `User.posts: type thunk returned undefined — is Post imported?`. In development, `emitSchemaFile` writes sorted SDL to `schema.graphql` by default.
- **Testing:** `@hpmws/testing` provides `app.graphql(query, { variables })` and `app.graphqlSubscribe(query)`. Their `path` option (and `app.request(method, path)`) is resolved against the test server's URL, so an absolute URL is followed to whatever host it names, headers included: pass paths, never URLs built from untrusted input.
- **Leaven integration:** Leaven's WebSocket handler, subscription manager and PubSub log through the application `LOGGER` (with its credential redaction), and its operation-type check parses with the executor's `parseOptions`. The pinned playground asset and inline-script hashes (`PLAYGROUND_ASSETS`, `PLAYGROUND_SCRIPT_HASHES`) match `@leaven-graphql/playground` 0.2.2 (`graphql-playground-react` 1.7.28) and must be recomputed when Leaven is upgraded.

`bun add @hpmws/core @hpmws/http @hpmws/graphql graphql` (`@hpmws/core`, `@hpmws/http` and `graphql@^16` are peer dependencies). Leaven is pre-1.0, so its packages are pinned exactly (`core` and `ws` `0.2.3`, `playground` `0.2.2`, `errors` `0.2.1`). Licensed MIT OR Apache-2.0.
